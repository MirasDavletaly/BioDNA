# BioDNA — детекция рака груди классическим машинным обучением

Определяет опухолевую ткань по профилю экспрессии генов, проверяет, ловится ли
**ранняя стадия**, и привязывает каждый ген-маркер к **координатам в ДНК**
(сборка hg38): хромосома, позиция, цитобанд.

**Без нейросетей.** Только scikit-learn: логистическая и штрафованная регрессия,
LDA, PLS-DA, сжатые центроиды (PAM), SVM, случайный лес, Extra Trees,
градиентный бустинг, наивный Байес, k-NN, мягкое голосование и стекинг.
Ни torch, ни transformers, ни DNABERT.

В проекте два независимых исследования:

| | Что сравнивается | Норма — это кто | Запуск |
|---|---|---|---|
| **v1** | опухоль vs ткань рядом с опухолью | те же онкобольные | `python train.py` |
| **v2** | опухоль vs здоровые люди | **женщины без рака (GTEx)** | `python train_cohorts.py` |

v2 отвечает на главное возражение к v1: «норма» там была тканью, взятой рядом с
опухолью у тех же пациентов, а такая ткань уже несёт следы болезни. Ниже —
сначала v2, потому что результат там честнее.

# v2 — здоровые люди против рака

Полный отчёт: [results_v2/REPORT_V2.md](results_v2/REPORT_V2.md)

## Данные

Источник — **recount3**: все когорты пересчитаны одним пайплайном Monorail на
аннотации GENCODE v26. Без этого сравнивать TCGA с GTEx нельзя — разница
протоколов забьёт биологию.

| Группа | Что это | N |
|---|---|---|
| Здоровые (GTEx) | грудная ткань женщин **без рака** | 180 |
| Норма рядом (TCGA) | ткань возле опухоли у онкобольных | 111 |
| Опухоль (TCGA) | первичная опухоль молочной железы | 1115 |
| **Внешняя когорта (FUSCC, Шанхай)** | 360 опухолей + 88 норм, в обучении не участвует | 448 |

Основной набор — **1406 образцов × 15 808 генов** (protein-coding,
экспрессируются хотя бы в 20% образцов). Мужские образцы GTEx отброшены:
мужская грудная ткань отличается от женской принципиально, и модель выучила бы
пол, а не болезнь.

## Главные результаты

**Отпечаток когорты — AUC 1.0000.** Здоровые GTEx и TCGA-норма-рядом
различаются идеально, хотя рака нет ни в одной из групп. Никакая нормировка
внутри образца этого не убирает. Значит наивная склейка «норма из GTEx,
опухоль из TCGA» меряет консорциум, а не болезнь — и даёт свои бесполезные
AUC 1.0.

**Перенос TCGA → GTEx — 0 ложных тревог из 180.** Модель, обученная
исключительно внутри TCGA и не видевшая ни одного образца GTEx, не назвала
больной ни одну здоровую женщину. Другой консорциум, другой протокол забора
ткани — сигнал переносится.

**Перенос GTEx → TCGA — провал 65–84%.** Обратное направление ломается: когда
норма в обучении приходит только из GTEx, модель понимает под нормой «похоже на
GTEx» и объявляет TCGA-норму опухолью. Вывод: норму надо брать из обоих
источников.

**Размер панели решает переносимость.** Внутри одной когорты качество на плато
при любом размере, но перенос — нет:

| Генов в панели | 10 | 25 | 50 | 100 | 200 | 500 |
|---|---|---|---|---|---|---|
| Ложных тревог у здоровых (лучшая нормировка) | 0.6% | 0.0% | **0.0%** | 0.6% | 3.3% | 3.3% |

Чем больше генов, тем больше шансов зацепиться за особенности консорциума.
Итоговая модель — **50 генов**, нормировка `zsample`.

**Перестановочный тест.** Метки перемешаны по пациентам, 100 прогонов:
AUC 0.5006 ± 0.0272 против настоящих 0.9998, p = 0.0099. Утечки в пайплайне нет.

### Внешняя валидация: Шанхай

Самая честная цифра проекта. **FUSCC** (Fudan University Shanghai Cancer
Center, SRP157974) — 360 первичных **трижды-негативных** опухолей и 88 парных
норм. Другая страна, больница, популяция и молекулярный подтип: TCGA
преимущественно ER-положительный. Ни один образец не участвовал ни в обучении,
ни в выборе нормировки и размера панели, ни в подборе порога.

| Метрика | Значение | 95% ДИ |
|---|---|---|
| ROC-AUC | **0.9790** | 0.9576 – 0.9943 |
| Чувствительность (360 опухолей) | **90.6%** | 87.1 – 93.2% |
| Специфичность (88 норм) | **97.7%** | 92.1 – 99.4% |

Падение AUC с 0.997 на своём тесте до 0.979 на чужой когорте — нормальная цена
переноса. У модели, которая держалась бы на утечке, здесь было бы около 0.5.

## Запуск v2

```bash
python train_cohorts.py              # ~64 мин, качает ~230 МБ recount3 один раз
python train_cohorts.py --report-only        # перегенерировать отчёт без обучения
python train_cohorts.py --panel-sizes 10 50 100   # свой перебор размеров панели
```

`predict_v2.py` ждёт покрытия генов в формате recount3 (gene_sums: строки —
Ensembl ID с версией, столбцы — образцы) и сам приводит их к log2(TPM+1) с той
же нормировкой, что при обучении.

# v1 — опухоль против прилежащей нормы

Полный отчёт: [results/REPORT.md](results/REPORT.md)

## Данные

`TCGA-BRCA`, микрочипы Agilent, log2-отношения: **61 норма и 529 опухолей,
17 814 генов**. Клинические стадии подтягиваются из **GDC API** по баркодам
TCGA (в самих файлах их нет): I — 89, II — 298, III — 110, IV — 13.

Координаты генов берутся из **UCSC refFlat + cytoBand (hg38)**, устаревшие
символы разрешаются через синонимы **NCBI gene_info** (`WISP1 → CCN4`,
`PPAPDC1A → PLPP4`) — благодаря этому локус находится для **17 053 из 17 814**
генов, а не для 14 472.

## Результаты

| Модель | CV ROC-AUC | Тест ROC-AUC | Чувств. | Спец. |
|---|---|---|---|---|
| **Logistic Regression (L2)** ⭐ | 1.0000 ± 0.0000 | 1.0000 | 1.000 | 1.000 |
| SVM (RBF) | 1.0000 ± 0.0000 | 1.0000 | 1.000 | 0.917 |
| Random Forest | 0.9995 ± 0.0010 | 0.9992 | 1.000 | 0.917 |
| Naive Bayes | 0.9951 ± 0.0024 | 0.9536 | 0.991 | 0.917 |

Стадия I распознаётся так же, как поздние (16/16 на тесте). Плато качества
достигается на **3 генах**.

## Почему цифрам v1 можно верить

1. **Отбор генов внутри пайплайна.** `SelectKBest` обучается только на
   train-фолде. В первой версии проекта отбор шёл по всей выборке — это утечка,
   которая сама по себе рисует AUC 1.000 на пустом месте.
2. **Разбиение по пациентам** (`StratifiedGroupKFold`): у части больных есть и
   опухоль, и своя же прилежащая норма; случайный сплит растащил бы их по
   train/test, и модель училась бы узнавать пациента.
3. **Контроль батч-эффекта.** Если оставить только 4 плашки, содержащие оба
   класса сразу (38 норма / 189 опухоль), CV ROC-AUC остаётся 1.0000 — значит
   различается ткань, а не партия реактивов.
4. **Победитель выбирается по кросс-валидации, не по тесту.**

Настоящая причина высоких цифр проста: опухолевая ткань молочной железы и
прилежащая нормальная ткань различаются по экспрессии очень сильно. Это
известное свойство TCGA-BRCA, а не заслуга модели. Именно поэтому появился v2.

## Запуск v1

```bash
python train.py                              # ~4 минуты
python train.py --n-genes 50
python train.py --target-sensitivity 0.99
python train.py --offline                    # без обращений в интернет

python predict.py --self-test
python predict.py --sample data/BC-TCGA-Tumor.txt --limit 5 --explain
```

# Что этот проект НЕ делает

Задача решается на **ткани**: образец уже взят при биопсии или операции. Это
подтверждение диагноза и молекулярная характеристика опухоли, а не скрининг по
анализу крови. «Раннее выявление» здесь означает «**ранняя стадия
распознаётся не хуже поздней**», а не «рак виден до появления симптомов».

Остаётся принципиальная асимметрия: единственные в наборе люди **без рака** —
доноры GTEx. Нормы в TCGA и в шанхайской когорте взяты у онкобольных рядом с
опухолью. Доказано, что модель отличает опухолевую ткань от неопухолевой и не
считает больными здоровых женщин из другой когорты. Не доказано, что она
отличила бы раннюю опухоль у человека, у которого её ещё не нашли: таких
образцов в открытых данных нет.

> Исследовательский проект. Не медицинское изделие и не основание для
> клинических решений.
